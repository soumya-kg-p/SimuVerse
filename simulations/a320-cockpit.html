    A320 VR cockpit — hands-only development blueprint

    Target: seated captain's-seat experience on Meta Quest (standalone + PC link) or PC VR, interacting only through tracked hands or controllers. This page is a working web prototype of the interaction model described below.

    1. System architecture & tech stack

    Engine choice

    Layers

    1. XR layer: OpenXR runtime, XR Plug-in Management, Meta XR Core SDK + Interaction SDK (Poke, Grab, Ray, Hand pose, Haptics). Fall back to XRI if you must stay vendor-neutral.
    2. Cockpit layer: one prefab per control type (push button, toggle, guarded switch, rotary knob, lever, slider, window). Each control reads a JSON map entry: {id, type, simVar, event, min, max, detents, hapticProfile}.
    3. Bridge layer: a small Windows service next to the sim that speaks to the sim and exposes WebSocket (JSON, 30–60 Hz push) to the headset app. Standalone Quest talks to it over Wi-Fi 6; PC-link builds can call it in-process.
    4. Sim layer: MSFS 2020/2024 or X-Plane 12 with an A320 add-on.

    Sim integration

    • MSFS + FlyByWire A32NX (free, open source): SimConnect for standard SimVars/events; MobiFlight WASM module to read/write L: variables and fire H: events (the A32NX cockpit is driven almost entirely by L:vars such as the A32NX_* family). Use SimConnect client-data areas for efficient batched reads.
    • X-Plane 12: UDP datarefs / commands (XPlaneConnect or a small XPLM plugin) with ToLiss, FlightFactor or Zibo-style Airbus add-ons.
    • Hardware option: an ESP32 glove (as in this page) posts finger flex JSON over HTTP/WebSocket; poll at 80 ms or less, prefer WebSocket push.
    • Authority rule: the sim owns truth. The headset sets the local animation instantly (optimistic UI) and reconciles when the sim value arrives.

    Build order

    1. Greybox cockpit at 1:1 scale from A320 drawings, seat eye-point at ~(0, 1.22 m).
    2. Bridge with five test controls (BAT1, EXT PWR, ADIRS knob, throttle, flaps).
    3. Control prefab library + JSON map for all ~150 overhead/pedestal controls.
    4. Procedure engine (this page's task list) driven by sim state.
    5. Audio, lighting, comfort, optimisation.

    2. Cockpit ergonomics & hand mechanics

    • Interactors: a Poke interactor on each index fingertip for pushbuttons and toggles; a Grab interactor (pinch / palm) for knobs, levers, window; a Ray interactor only as an accessibility/far fallback, never active at the same time as Poke on the same hand.
    • Push buttons (BAT, EXT PWR, pumps, APU): poke with 6–8 mm travel, latch past 70 % depth, release at 40 % (hysteresis). Face light changes state only when the sim confirms.
    • Toggle switches (exterior lights, ENG masters): grab or poke-flick; hinge constrained to ±30°, snap to the nearer end, 2-stage click haptic.
    • Rotary knobs (ADIRS, ENG MODE): grab + twist; map wrist roll delta to knob angle with a 0.3 gain, snap to detents every 40–60°. Drag-sideways fallback for hand tracking.
    • Throttle levers: grab constrained to one axis, value clamped 0–1, magnetic detents at IDLE, CLB/MCT, TOGA with a haptic tick; both levers can be gripped together with a wide hand.
    • Flaps lever / sliding window: axis-constrained translate along a rail with discrete detents (flaps) or continuous (window).
    • Haptics (controllers): hover enter 0.1 amp / 10 ms; press 0.5 / 25 ms; detent 0.35 / 15 ms; stop-end 0.7 / 40 ms. Bare-hand: audio click + visible depress + optional glove vibration motor.
    • Hand visuals: keep the rendered hand "pinned" to the control surface while interacting (visual-penetration clamp) so fingers never pass through panels.
    • Reach: overhead is above natural arm range — allow a 15° seat recline offset or raise the hand-reach "virtual arm" by 10 % for overhead only.

    3. Cold & dark to taxi — procedure checklist

    Items marked ★ are in this prototype. Real timings are longer; this build uses an accelerated ADIRS (≈15 s) and APU (≈12 s).

    A. Electrical power-up

    1. ★ BAT 1 and BAT 2 pushbuttons — ON (OFF light extinguishes).
    2. ★ EXT PWR — AVAIL green → push ON. AC BUS 1/2 powered.
    3. Check ECAM ELEC page: voltages, no amber.

    B. Systems alignment

    1. ★ ADIRS 1, 2, 3 selectors — NAV.
    2. ★ Wait for alignment; PFD ATT/HDG/SPD flags clear. (Real: ≈ 10 min, ~1 min with fast align.)
    3. Enter position/route in MCDU (INIT A, INIT B, F-PLN, PERF) — planned next module.

    C. APU and bleed

    1. ★ APU MASTER — ON.
    2. ★ APU START — ON; ★ wait for AVAIL.
    3. ★ APU GEN — ON (EXT PWR drops off line).
    4. ★ APU BLEED — ON.

    D. Flight preparation

    1. ★ Fuel pumps — all ON.
    2. ★ BEACON — ON.
    3. ★ Flaps — set for take-off (config 1+F shown).
    4. Set altimeters, transponder, seat-belt / no-smoking signs, trim, load sheet cross-check.

    E. Engine start

    1. ★ ENG MODE — IGN/START.
    2. ★ ENG 2 MASTER — ON; ★ wait for stable idle (N2 passes starter cut-out, EGT stable).
    3. ★ ENG 1 MASTER — ON; ★ wait for stable idle.
    4. ★ ENG MODE — NORM.

    F. Before taxi

    1. ★ NAV & LOGO — ON; taxi light, strobes as required.
    2. ★ Release PARK BRK.
    3. ★ Advance both throttles gently for taxi thrust (outside world starts to move).
    4. Flight-control check, ECAM memo clean, clearance received.

    4. Immersive VR features

    • Interactive cabin items (★ in prototype): coffee cup you lift to your face, sun visor, cabin CALL button with chime. Next: tray table, cockpit door with keypad, flight bag, headset hook, tablet (EFB) you hold.
    • Opening windows with ambient sound (★): the captain's sliding window drags open; the audio mixer cross-fades from a muffled interior bed to wind, apron and ground-crew sound. Add real occlusion: low-pass cutoff = f(window openness) per emitter.
    • Spatial audio: engine spool from the correct side, APU whine from behind, ECAM chimes inside the cockpit, ground power hum when EXT PWR is connected.
    • Room-scale / seat-scale: a one-time seat calibration (sit, press "Set eye-point"); lean ±35 cm to look around the glareshield; optional stand-up mode that teleports to the jump-seat or walks the guardian boundary to the cabin door.
    • Environment: day/night/dusk presets, dynamic sun through the windshield, rain on glass, vibration cue on engine start (very low amplitude, comfort-safe), passthrough "coffee-table" mode to see a real keyboard/MCDU.
    • Instruction layer: amber AR rings on the next control (★), a hand-ghost demo, instructor mode streaming scores over WebSocket.

    5. Core challenges & solutions

    ProblemSolution
    Hand-tracking jitterOne-Euro filter on fingertip and wrist (low cutoff when slow, high when fast) — ★ used here; confidence gating (freeze last pose below 0.5); controller fallback; magnet/sticky hover with 150–200 ms release grace.
    Accidental presses in a cramped panelIndex-tip-only poke collider (3–5 mm); required hover dwell (60–150 ms) before a press counts — ★; press depth + hysteresis; ignore pokes while the hand moves faster than ~1.2 m/s; 150 ms post-release lockout — ★; guarded covers for critical switches (ENG FIRE, EVAC); disable overhead interactors when the head is not looking up; "safe hand" palm-up gesture.
    Input latencyRun interaction locally (set animation instantly, reconcile with sim); WebSocket/UDP push at 30–60 Hz instead of HTTP polling (original glove poll 500 ms → 80 ms here); batch SimVar reads; avoid per-frame allocations; target 72–90 Hz render, fixed foveated rendering, async reprojection (ATW/ASW); budget: head motion-to-photon < 20 ms, press-to-sim < 100 ms.
    ComfortNo artificial camera motion except slow taxi (world slides at ≤ 15 kt), vignette on speed, 90° snap options, persistent cockpit frame as a visual anchor.
    Performance on QuestBaked lighting, texture atlases for panel faces, GPU instancing for switches, LODs on seats/cabin, render screens at 512² and update at 5–10 Hz.
